AIA Internal Technology Group
数据安全政策
版本：1.0
负责人：Security Operations Team

1. 目的

本数据安全政策用于规范 AIA Internal Technology Group 内部系统、日志数据、研发文档、个人信息和敏感凭证的处理方式。该政策适用于 AKP Platform 及相关技术系统。

2. 数据分类

公司数据分为公开数据、内部数据、机密数据和受限数据。

公开数据是已经批准对外发布的信息。
内部数据仅限公司员工和授权合同人员访问。
机密数据包括业务计划、技术设计、系统配置、运行日志和内部报告。
受限数据包括个人信息、访问令牌、API Key、密码、私有证书和安全事件细节。

3. 个人信息处理

员工在处理个人信息时，应遵循最小必要原则。只有在具有明确业务目的和授权的情况下，才可以访问个人信息。

包含个人信息的文档、日志或导出文件不得存放在个人设备、个人网盘或未批准的外部系统中。

4. 敏感数据脱敏

在日志、测试数据、问题排查报告和 AI 分析结果中，应对邮箱、手机号、身份证号、员工 ID、访问令牌、API Key 和密码进行脱敏处理。

例如，邮箱应替换为 [EMAIL]，手机号应替换为 [PHONE]，API Key 或访问令牌应替换为 [REDACTED_SECRET]。

5. API Key 管理

API Key、访问令牌和密码不得写入源代码、配置模板、测试用例、日志文件或公开代码仓库。

如果系统必须使用 API Key，应通过环境变量、密钥管理服务或受控配置中心进行加载。

如果发现 API Key 泄露，相关团队必须立即吊销旧 Key，生成新 Key，并在 24 小时内提交安全事件报告。

6. 日志安全

系统日志不得记录明文密码、完整访问令牌、完整 API Key 或未脱敏的个人信息。

日志应包含足够的诊断信息，例如 request_id、session_id、user_action、service_name、latency_ms、error_code 和 result_status。

日志访问权限应受到限制，只有具备排查职责的工程师、安全人员和系统负责人可以访问相关日志。

7. 权限审批

访问生产环境、敏感日志、客户相关数据或 AKP Platform 管理后台时，必须通过权限审批流程。

权限审批应包括申请人、申请原因、访问范围、有效期、审批人和系统负责人确认。

8. 安全事件处理

如果员工发现疑似数据泄露、异常访问、恶意请求、凭证泄露或日志中出现敏感信息，应在 24 小时内通知 Security Operations Team。

安全事件处理应包括影响范围确认、风险隔离、凭证轮换、日志分析、根因定位和后续改进措施。
